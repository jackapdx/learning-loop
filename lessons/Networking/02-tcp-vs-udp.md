# TCP vs UDP: ความถูกต้อง vs ความเร็ว (Trade-off ของความเร็วแสง)

---

## 🎯 ปฐมนิเทศ (Orient)

*"คุณยอมรับได้ไหมถ้าเพื่อนพูด 10 ประโยคแล้วหายไป 1 ประโยค? แล้วถ้าเป็นเงินในบัญชีที่หายไป 1 บาทล่ะ?"* การเลือกโปรโตคอลการสื่อสารคือการเลือกระหว่าง **ความแม่นยำ (Accuracy)**และ**ความเร็ว (Real-time)** หากคุณเลือกผิดแอปของคุณอาจจะช้าอืดอาดจนคนเลิกใช้ หรือข้อมูลผิดพลาดจนบริษัทล้มละลาย บทเรียนนี้จะสอนวิธีเลือกใช้ TCP และ UDP แบบมือโปร

## 💬 ผลตอบรับ (Feedback)

| หากคุณตอบว่า... | การวิเคราะห์ |
|:---|:---|
|"TCP (Reliable)" | ⚠️ **เกือบใช่!**TCP จะพยายามส่งข้อมูลที่หายไปใหม่ (Retransmission) ทำให้ภาพค้างและเกิด Latency สะสมจนคุยกันไม่รู้เรื่อง |
|"UDP (Low Latency)" | ✅ **นี่คือคำตอบ!**สำหรับ Video Stream เรายอมให้"บางเฟรม" หายไปได้ แต่เราต้องการความเร็วสูงสุด ข้อมูลใหม่สำคัญกว่าข้อมูลเก่าที่หายไป |
|"HTTP (Rest API)" | ❌**ผิดทาง!**HTTP ส่วนใหญ่รันบน TCP และมี Overhead สูงเกินไปสำหรับงาน Real-time ⏰ streaming |

**ทำไมคนส่วนใหญ่ถึงพลาด?**เพราะเราถูกสอนมาว่า"ข้อมูลห้ามหาย" แต่ในโลกของ Real-time ⏰ ข้อมูลที่"มาช้าเกินไป" ก็มีค่าเท่ากับ"ข้อมูลที่หายไป" หรือแย่กว่านั้น

### คำอธิบาย (Explain)

การเลือกระหว่าง TCP และ UDP คือการเลือกจุดสมดุลระหว่างความถูกต้อง (Integrity) และความเร็ว (Throughput) ตามลักษณะความสำคัญของข้อมูล [source: Cloudflare Learning Center — TCP vs. UDP]

### 1. TCP (Transmission Control Protocol)

เหมือนการส่ง**"จดหมายลงทะเบียน"**:
-**3-Way Handshake:**ต้องมีการทักทายและยืนยันตัวตนก่อนส่งข้อมูล (SYN, SYN-ACK, ACK)
-**Reliable:**ถ้าข้อมูลหาย จะมีการส่งใหม่จนกว่าจะได้รับ (Retransmission)
-**Ordered:**ข้อมูลจะถึงมือผู้รับตามลำดับที่ส่งไปเสมอ
-**Flow Control:**ปรับความเร็วการส่งตามที่ผู้รับจะรับไหว

### 2. UDP (User Datagram Protocol)

เหมือนการส่ง**"จดหมายธรรมดา"**:
-**Connectionless:**ส่งไปเลยไม่ต้องรอตอบรับ (Fire and Forget)
-**Unreliable:**ข้อมูลหายแล้วหายเลย ไม่มีการส่งใหม่
-**No Ordering:**ข้อมูลอาจถึงสลับลำดับกันได้
-**Lightweight:**ไม่มี Overhead เรื่องการตรวจสอบ ทำให้เร็วที่สุดเท่าที่สายแลนจะทำได้

### ตารางเปรียบเทียบ

| คุณสมบัติ | TCP | UDP |
|:---|:---:|:---:|
|**ความน่าเชื่อถือ**| สูง (ห้ามหาย) | ต่ำ (หายได้) |
|**ความเร็ว / Latency**| ต่ำ (ช้ากว่า) | สูง (เร็วกว่า) |
|**การจัดลำดับ**| มี (Sequence Number) | ไม่มี |
|**เหมาะสำหรับ**| Web, Email, File Transfer, Database 📦 | Streaming, Gaming, VoIP, DNS |

## 🔬 ขยายความ (Extend)

### เทคนิค Senior: เมื่อไหร่ควรใช้ UDP + Custom Reliability?

บางครั้งเราต้องการความเร็วของ UDP แต่ก็อยากให้ข้อมูล"สำคัญ" บางอย่างไม่หาย (เช่น คำสั่งยิงในเกมออนไลน์):
-**QUIC (HTTP/3):**โปรโตคอลใหม่ของ Google ที่รันบน UDP แต่สร้างระบบ Reliability ขึ้นมาเองข้างบน เพื่อให้เร็วกว่า TCP แต่ยังปลอดภัย
-**WebRTC:**ใช้ UDP สำหรับส่งภาพ/เสียง แต่ใช้ TCP สำหรับส่งคำสั่งควบคุม (Signaling)

### กลยุทธ์การรับมือ Network Jitter ใน UDP

ในแอปวิดีโอคอล เราใช้สิ่งที่เรียกว่า**"Jitter Buffer"**:
- เก็บข้อมูลที่มาถึง (ซึ่งอาจจะสลับลำดับกัน) ไว้ใน Buffer สั้นๆ (เช่น 50ms)
- จัดลำดับใหม่ให้ถูกต้องก่อนนำไปแสดงผล
- หากข้อมูลมาช้าเกินไป (เกิน 50ms) ให้ทิ้งไปเลย (Drop) เพื่อรักษาความเป็น Real-time ⏰

## ✅ จุดตรวจสอบ (Checkpoint)

🎯**Quick Check:**ในการส่งไฟล์ ZIP ขนาด 1GB คุณควรใช้โปรโตคอลไหน? เพราะอะไร?
ทำไมเกมออนไลน์แนว FPS ถึงเลือกใช้ UDP แม้ว่าปัญหากระสุนหาย (Ghost shots) จะเกิดขึ้นได้?
"3-Way Handshake" เป็นขั้นตอนของโปรโตคอลใด?

<details>
<summary>ดูเฉลย (คลิกเพื่อเปิด)</summary>**TCP**เพราะไฟล์ ZIP ถ้าข้อมูลหายแม้แต่ Bit เดียวไฟล์จะเสียและแตกไฟล์ไม่ได้**UDP**เพราะ Latency สำคัญที่สุด หากใช้ TCP แล้วเน็ตกระตุก ตัวละครในเกมจะค้าง (Lag) และวาร์ปไปมา ซึ่งทำลายประสบการณ์การเล่นมากกว่า**TCP**(ใช้เพื่อสร้างความมั่นใจว่าทั้งสองฝั่งพร้อมสื่อสารกัน)
