# พลังทำลายล้าง (Blast Radius) และรั้วกั้นอัตโนมัติ (Guardrails)

---

## ปฐมนิเทศ (Orient)

*"การลบข้อมูล 5 เครื่อง กับการลบข้อมูล 5,000 เครื่อง ใช้เวลาในคำสั่ง (Enter) เท่ากัน"* นี่คือความน่ากลัวของระบบอัตโนมัติ (Automation) ในยุค Cloud หากคุณไม่มีการจำกัด **Blast Radius **(รัศมีทำลายล้าง) ความผิดพลาดเพียงเล็กน้อยของวิศวกรคนเดียว อาจทำให้บริษัทระดับโลกล่มไปทั้งภูมิภาคเหมือนเหตุการณ์ AWS S3 ในปี 2017 บทเรียนนี้จะสอนวิธี"สร้างกรง" ขังความผิดพลาดไม่ให้ลุกลาม

### คำอธิบาย (Explain)

ในระบบขนาดใหญ่ ความผิดพลาดเป็นสิ่งที่หลีกเลี่ยงไม่ได้ แต่เราสามารถควบคุม"ขอบเขตความเสียหาย" (Blast Radius) ไม่ให้ขยายวงกว้างจนกระทบผู้ใช้ทั้งหมด [source: Google SRE Book — Release Engineering]

### 1. Blast Radius คืออะไร?

คือขอบเขตสูงสุดที่จะได้รับผลกระทบหากส่วนประกอบหนึ่งพัง
-**Bad Design:** หนึ่งความผิดพลาด ทำระบบล่ม 100% (Blast Radius = Global)
-**Good Design:** หนึ่งความผิดพลาด ทำระบบล่ม 1% (Blast Radius = Cell/Partition)

### 2. กลยุทธ์การจำกัด Blast Radius
**Cell-based Architecture 🏗️:** แบ่ง Infrastructure 🏗️ เป็น"กรง" (Cells) ที่แยกขาดจากกันอย่างสิ้นเชิง หาก Cell A พัง ลูกค้าใน Cell B จะไม่รู้สึกอะไรเลย
**Regional Isolation:** ห้ามให้ Service ใน Region หนึ่ง ต้องพึ่งพา Service ในอีก Region หนึ่งในระดับ Runtime
**Control Plane vs. Data Plane:** แยกส่วนที่ใช้"สั่งการ" ออกจากส่วนที่ใช้"รับส่งข้อมูล" เพื่อไม่ให้ระบบจัดการทำระบบทำงานพังไปด้วยกัน

## ขยายความ (Extend)

### Automation Guardrails: รั้วกั้นมนุษย์
อย่าพึ่งพาแค่สติของวิศวกร ให้พึ่งพาระบบ:
-**Rate Limiting Deployments:** ไม่อนุญาตให้ Deploy เกิน n% ของ Fleet พร้อมกัน
-**Semantic Validation:** ก่อนจะ Apply Config ใหม่ ระบบต้องเช็คว่า"ค่าใหม่นี้ดูสมเหตุสมผลไหม?" (เช่น ถ้าค่าเดิมคือ 10 แต่ค่าใหม่คือ 10,000 ให้บล็อกทันที)
-**Automatic Rollback:** หาก Error Rate พุ่งสูงขึ้นหลังจาก Deploy ให้ระบบสั่ง Rollback กลับเวอร์ชันเก่าทันทีโดยไม่ต้องรอคนกด

### กรณีศึกษา: CrowdStrike (2024)

```text
เหตุการณ์ที่คอมพิวเตอร์ Windows ล่มทั่วโลกเกิดจาก **Global Deployment ** ที่ไม่มี Guardrail:
- ไฟล์คอนฟิกที่ผิดพลาดถูกส่งไปยังคอมพิวเตอร์"ทุกเครื่อง" พร้อมกัน
-** บทเรียน:** แม้แต่ไฟล์ข้อมูล (Content Update) ก็ต้องมีการทำ Canary Rollout เหมือนโค้ด
```
